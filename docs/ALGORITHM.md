# Русскоязычный алгоритм

## Предобработка

В обучении и прогнозе используется одна функция `normalize_text`: Unicode NFKC,
нижний регистр, `ё` → `е`, сохранение кириллицы, латиницы и цифр, нормализация пробелов.
`не`, `ни`, `нет`, `без` сохраняются. IMDb и английские stopwords не используются.

## Два режима

Без артефакта: словарные признаки позитивного/негативного текста, обработка локальных
отрицаний, деление на части по пунктуации и «но/однако/зато», привязка оценочных слов
к ближайшему аспекту. Отзыв с противоположными оценками даёт общий нейтральный
результат с `mixed=true`; оценки аспектов могут отличаться. Неизвестный текст также
нейтральный, но не считается доказательством нейтральности. `confidence=null`;
`needs_review=true`. Правила ограничены словарём и не решают надёжно сарказм,
дальний контекст и все варианты отрицания.

С доверенным артефактом: Pipeline предобработки → TF-IDF (слова и n-граммы) →
LogisticRegression, три класса. Вероятность `predict_proba` не является гарантией
правильности и не заменяет измерение качества. Аспекты остаются правилами, это
отдельный явно указанный компонент. Смешанные и незнакомые случаи требуют проверки.

## Корпус обучения

Одна JSON-строка на запись. Обязательные поля:

| Поле | Смысл |
|---|---|
| `text` | Реальный русский текст без ненужных персональных данных |
| `sentiment` | `positive`, `negative`, `neutral` |
| `source_url` | Проверяемая ссылка на источник |
| `split` | `train`, `validation`, `test` |
| `aspects` | Необязательные `[{"id":"dormitory","sentiment":"negative"}]` |

Разметка: общий эмоциональный вывод автора, не исходные звёзды. Противоречивые
отзывы обсуждать вручную; «нейтральный» и «непонятный» не смешивать без фиксации
решения. Аспекты: `teaching`, `career`, `dormitory`, `infrastructure`,
`administration`, `student_life`, `finance`. Размечайте каждый найденный аспект
отдельно. Не считайте отсутствие упоминания отрицательной оценкой.

Разделение выполняет владелец корпуса до обучения; необходимо группировать отзывы
одного автора/источника и близкие дубликаты, чтобы исключить утечки. Скрипт проверяет
точные дубликаты после нормализации, но не обнаруживает всех парафразов.
В `train` и `test` должны быть все три класса; validation нужна для выбора порога.
Не оценивайте модель на тренировочных данных.

## Отчёт и воспроизводимость

Скрипт сохраняет macro-F1, precision/recall/F1 по классам, confusion matrix,
сравнение с Dummy baseline, результаты валидации и выбранный порог. Если разметка
аспектов присутствует, вычисляются micro/macro-F1 правил. Данные и версии библиотек
фиксируются в метаданных артефакта. Отчёт и модель относятся только к переданному
корпусу; генерация «похожих» примеров не даёт оценки реальных вузовских отзывов.

## Рейтинг

Из пригодных подтверждённых записей каждого вуза считаются `P`, `N`, `U`.
Наблюдаемая доля: `100 × P / (P+N+U)`.
Сглаженный показатель: `100 × (P + m×p₀) / (P+N+U+m)`.
`p₀` — доля позитивных по всему пригодному корпусу до фильтрации интерфейса.
Место присваивается только при достижении опубликованного минимального размера
выборки. Отсутствие данных не превращается в нулевой рейтинг.
Рейтинг отзывов не измеряет объективное качество образования.

Сильные/слабые стороны — агрегаты аспектов с минимум тремя подтверждающими
упоминаниями; единичная жалоба не описывается как устойчивый недостаток.
Все агрегаты можно проверить по отзывам и SQL, а не по декоративным числам в HTML.
