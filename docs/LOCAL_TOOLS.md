# Локальные инструменты администратора и исследователя

Эта инструкция нужна для отдельной Python-версии с SQLite, импортом отзывов,
ручным аудитом и обучением модели. Обычному посетителю сайта и для публикации
на GitHub Pages эти шаги не нужны: [инструкция для сайта](GITHUB_PAGES.md).

Локальная база не обновляет опубликованный сайт автоматически. Канонические
публичные данные сайта находятся в `website/data`; правила их обновления
описаны в [инструкции GitHub Pages](GITHUB_PAGES.md#обновить-каталог-и-отзывы).
Для постоянно работающего Flask-сервера требуется отдельный хостинг Python.

## Полный запуск на Windows

### 1. Скачать и распаковать проект

Откройте [репозиторий](https://github.com/Sweaty6/Baknin_Project), нажмите
**Code → Download ZIP** и распакуйте архив средствами Windows. Можно использовать
и готовый архив проекта. Не запускайте файлы внутри самого ZIP.

Найдите распакованную папку с файлами `app.py` и `requirements.txt`.
При скачивании с GitHub она обычно называется `Baknin_Project-main`.
В Проводнике откройте эту папку, щёлкните адресную строку, введите `powershell`
и нажмите Enter. Откроется PowerShell в нужном каталоге.

Если открыли PowerShell отдельно, перейдите в папку командой, заменив путь своим:

```powershell
cd "C:\Users\ВашеИмя\Downloads\Baknin_Project-main"
Get-ChildItem app.py, requirements.txt
```

Последняя команда должна показать оба файла. Если их нет, выбрана другая папка.

### 2. Установить Python

Нужен **Python 3.11 или 3.12, 64-бит**. Его можно установить с
[официального сайта Python](https://www.python.org/downloads/windows/).
При установке включите **Add python.exe to PATH** и Python Launcher, если этот
пункт доступен. После установки закройте PowerShell и откройте его снова.

Проверьте доступные версии:

```powershell
py -0p
py -3.11 --version
```

Далее приведены команды для 3.11. Если установлен 3.12, замените только
`py -3.11` в следующем шаге на `py -3.12`.

### 3. Один раз установить зависимости и создать базу

Выполняйте команды по одной и дождитесь завершения каждой:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m baknin.cli init
```

Установка зависимостей требует интернета и может занять несколько минут.
В конце инициализации выводятся `universities: 5` и `reviews_seeded: 0`.
Создаётся локальная база `instance\baknin.sqlite3`.

Команды вызывают Python из `.venv` напрямую, поэтому активировать окружение
и менять PowerShell ExecutionPolicy не требуется. Старую папку `venv`,
скопированную с другого компьютера, использовать не нужно.

### 4. Запустить и открыть сайт

```powershell
.\.venv\Scripts\python.exe app.py
```

Оставьте это окно открытым. Отсутствие нового приглашения PowerShell означает,
что сервер продолжает работать. Откройте в браузере **http://127.0.0.1:5000/**.
Для проверки откройте **http://127.0.0.1:5000/health**: при обычном запуске JSON
содержит `status: "ok"`, `database: "ready"`, `engine: "rules"`
и `ml_trained: false`.

На странице анализа можно проверить фразу
«Отличные преподаватели, но общежитие плохое». Это технический пример для ввода,
он не добавляется в рейтинг.

Для остановки нажмите **Ctrl+C** в окне сервера. На следующий день снова
откройте PowerShell в папке проекта и выполните только:

```powershell
.\.venv\Scripts\python.exe app.py
```

Повторная установка пакетов и создание окружения для каждого запуска не нужны.
Отдельные HTML-файлы из `templates` открывать двойным щелчком не нужно:
полная версия получает данные от работающего сервера.

## Если запуск не получается

| Сообщение или ситуация | Что сделать |
|---|---|
| `py` не найден | Переоткройте PowerShell после установки Python. Если работает `python --version` и это 3.11/3.12, создайте окружение командой `python -m venv .venv`. |
| `No suitable Python runtime found` | Установите нужную версию или используйте `py -3.12`, если установлена 3.12. |
| `requirements.txt` или `app.py` не найден | Перейдите в распакованную папку, где лежат оба файла. |
| `No module named flask` или `waitress` | Запустите установку через `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и затем используйте тот же Python. |
| Браузер не открывает `127.0.0.1:5000` | Убедитесь, что сервер запущен, окно не закрыто и в нём нет ошибки. |
| Порт 5000 занят | Выполните `$env:PORT = "5001"`, затем команду запуска. Откройте `http://127.0.0.1:5001/`. |
| Ошибка скачивания зависимостей | Проверьте интернет и полный текст ошибки; не отключайте проверку сертификатов. |
| `/health` возвращает `degraded` | Проверьте путь к подключённой модели и её метаданные. Для возврата к правилам выполните `Remove-Item Env:BAKNIN_MODEL -ErrorAction SilentlyContinue` и перезапустите сервер. |

## Linux и macOS

В терминале перейдите в распакованную папку проекта. Проверьте, что `python3`
имеет версию 3.11 или 3.12. Затем:

```bash
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m baknin.cli init
.venv/bin/python app.py
```

Откройте `http://127.0.0.1:5000/`. Остановка — Ctrl+C; последующие запуски —
только `.venv/bin/python app.py`. На Linux отсутствие модуля `venv` устраняется
установкой пакета `python3-venv` для используемой версии средствами дистрибутива.

## Добавить настоящие отзывы

В полном проекте база и импорт работают локально. Подготовьте UTF-8-файл JSONL
с реальными проверенными отзывами: один JSON-объект на строку, точная ссылка
на источник, даты и идентификатор вуза. Полная схема и условия показа текстов
описаны в [data/README.md](../data/README.md). Готового корпуса и скрейпера в
проекте нет; случайные примеры из интернета не заменяют проверенные данные.

Сохраните свой файл, например, как `instance\verified-reviews.jsonl` и выполните:

```powershell
.\.venv\Scripts\python.exe -m baknin.cli import --input .\instance\verified-reviews.jsonl
.\.venv\Scripts\python.exe -m baknin.cli audit
```

Вторая команда показывает очередь ручной проверки. Для подтверждения конкретного
отзыва, например с ID `12`, используйте его фактическую оценку:

```powershell
.\.venv\Scripts\python.exe -m baknin.cli audit 12 --sentiment positive --actor reviewer --note "Проверен исходный текст"
```

Значения тональности: `positive`, `neutral`, `negative`. `12` в примере —
место для ID из вашей очереди, а не готовый отзыв. Темы требуют отдельной проверки;
параметр `--aspects` и формат описаны в [описании формата](../data/README.md).
Рейтинг учитывает пригодные подтверждённые записи; по умолчанию для места нужно
не менее 10 отзывов на вуз. Обновите страницу после импорта и проверки.

Сохраняйте резервную копию `instance` при остановленном сервере. Эта папка
содержит локальные данные и не публикуется в GitHub.

## Обучение модели — необязательный отдельный шаг

Чтобы пользоваться сайтом и словарным анализом, обучение не требуется.
Для него нужен настоящий размеченный русскоязычный корпус с тремя классами
и отдельными `train`, `validation`, `test`. Формат — в
[docs/ALGORITHM.md](ALGORITHM.md). Файл корпуса в архив не входит.

```powershell
.\.venv\Scripts\python.exe model_training.py --input .\instance\labeled.jsonl --output .\instance\model.joblib --report .\instance\metrics.json
$env:BAKNIN_MODEL = (Resolve-Path .\instance\model.joblib).Path
.\.venv\Scripts\python.exe app.py
```

Подключайте только созданную вами доверенную модель. Вместе с `model.joblib`
нужен созданный обучением файл `model.joblib.json`. Старые англоязычные `.pkl`
из другого проекта несовместимы. Переменная, установленная этой командой,
действует только в текущем окне PowerShell: при следующем открытии окна её
нужно задать заново. На Pages этот Python-артефакт не используется.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `BAKNIN_DB` | `instance/baknin.sqlite3` | Путь к SQLite |
| `BAKNIN_MODEL` | не задана | Доверенная локальная модель, иначе правила |
| `BAKNIN_METRICS` | `instance/metrics.json` | Отчёт для подключённой версии модели |
| `BAKNIN_MIN_REVIEWS` | `10` | Минимум пригодных отзывов для места |
| `BAKNIN_SMOOTHING` | `10` | Параметр сглаживания `m` |
| `BAKNIN_HOST` | `127.0.0.1` | Адрес сервера |
| `PORT` | `5000` | Порт |

Минимум и сглаживание — **опубликованные пилотные настройки**, ещё не подобранные на
реальном корпусе. Перед публикацией содержательного рейтинга калибруйте их и
фиксируйте решение. Нейтральные отзывы включаются в знаменатель.
При ручной проверке аспектов используйте один аспект один раз на отзыв.

## Проверки

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тексты в тестах — искусственные технические фикстуры, изолированные во временных
БД. Они не являются корпусом студентов, не импортируются в рабочую базу и не
доказывают качество модели. Действительный отчёт macro-F1 появляется только
после обучения на предоставленном размеченном корпусе.
Отчёт выполненных проверок и ограничения: [ACCEPTANCE.md](ACCEPTANCE.md).
