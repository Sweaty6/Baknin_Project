# Бакнин — отзывы об аграрных вузах

Flask-приложение: каталог аграрных вузов, рейтинг из SQLite,
карточки вузов, отзывы с источниками, русскоязычный анализ и открытая методика.

**Статус данных:** в комплекте есть только справочник пяти аграрных вузов.
Реальных отзывов и обученной на них модели пока нет. Стартовая база пуста,
поэтому сайт показывает «Недостаточно данных», а не придуманные рейтинги.
Без обученного артефакта работает явно обозначенный словарный анализ.
Его качество на корпусе не измерено; результат требует проверки человеком.

## Быстрый запуск

Нужен Python **3.11 или 3.12**, 64-бит. Чужие `venv` из старых архивов не используйте.
Все команды выполняются из корня проекта.

Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m baknin.cli init
.\.venv\Scripts\python.exe app.py
```

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m baknin.cli init
.venv/bin/python app.py
```

Откройте `http://127.0.0.1:5000`. Сервер Waitress работает без режима debug.
Не открывайте HTML-файлы напрямую: страницы обращаются к Flask API.
Пакеты NLTK и IMDb для нового алгоритма не нужны.

Проверка PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/health
$body = @{ text = "Отличные преподаватели, но общежитие плохое" } | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:5000/predict -Method Post -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

## Что умеет проект

- Рейтинг с поиском, регионом и периодом; наблюдаемая доля позитивных отзывов и сглаженный показатель.
- Карточка вуза с распределением классов, динамикой, аспектами и подтверждающими отзывами.
- Фильтры отзывов по вузу, источнику, дате, тональности и теме; пагинация.
- Три класса тональности; семь аспектов; сохранение кириллицы и отрицаний.
- Отдельная оценка разных аспектов смешанного отзыва, фрагменты для объяснения.
- Импорт JSONL, дедупликация в пределах вуза, проверка метаданных и ручной аудит.
- Воспроизводимое обучение TF-IDF + LogisticRegression и отчёт на отложенной выборке.
- Адаптивный интерфейс без внешних CDN; пользовательский анализ не сохраняется в базу.

## Реальные данные и обучение

Формат импорта и требования к происхождению описаны в [data/README.md](data/README.md).
Сначала проверьте допустимость хранения и показа текстов, принадлежность вузу и удалите
ненужные персональные данные. Флаги в JSONL — заявление проверяющего, а не автоматическая
проверка прав или достоверности источника. Встроенного скрейпера нет.

```bash
.venv/bin/python -m baknin.cli import --input /path/to/verified-reviews.jsonl
```

Неразмеченные результаты правил не попадают в рейтинг до ручного аудита.
Команда `python -m baknin.cli audit --help` показывает порядок подтверждения.
Подтверждение общей тональности не подтверждает автоматически словарные темы.
Передайте `--aspects checked-aspects.json`, где явно проверены `aspect`, `sentiment`
и `context` (точная цитата исходного текста). Для очереди: `python -m baknin.cli audit`.

Для обучения нужен **реальный вручную размеченный** корпус с тремя классами и
явными `train`, `validation`, `test`. Файл не входит в комплект. Формат в
[docs/ALGORITHM.md](docs/ALGORITHM.md).

```bash
.venv/bin/python model_training.py --input /path/to/labeled.jsonl --output instance/model.joblib --report instance/metrics.json
```

Затем включите **только созданный вами доверенный** артефакт и перезапустите сервер:

```bash
export BAKNIN_MODEL="$PWD/instance/model.joblib"
.venv/bin/python app.py
```

PowerShell: `$env:BAKNIN_MODEL = (Resolve-Path .\instance\model.joblib).Path`.
Joblib использует pickle; неизвестные скачанные модели запускать нельзя.
Сохраняйте рядом с `model.joblib` файл `model.joblib.json`: это обязательные
метаданные и контрольная сумма; без него артефакт не загружается.
Старые англоязычные `.pkl` несовместимы с новым форматом и не загружаются автоматически.

`/health` показывает `engine`, `model_version` и `ml_trained`.
Существование файла модели не подтверждает её качество на реальных отзывах.
Показатель 88% из IMDb не используется.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `BAKNIN_DB` | `instance/baknin.sqlite3` | Путь к SQLite |
| `BAKNIN_MODEL` | не задана | Доверенная локальная модель, иначе правила |
| `BAKNIN_METRICS` | `instance/metrics.json` | Отчёт для подключённой версии модели |
| `BAKNIN_MIN_REVIEWS` | `10` | Минимум пригодных отзывов для места |
| `BAKNIN_SMOOTHING` | `10` | Параметр сглаживания `m` |
| `BAKNIN_HOST` | `127.0.0.1` | Адрес сервера |
| `PORT` | `5000` | Порт |

Минимум и сглаживание — **опубликованные пилотные настройки**, ещё не подобранные на
реальном корпусе. Перед публикацией содержательного рейтинга калибруйте их и
фиксируйте решение. Нейтральные отзывы включаются в знаменатель.
При ручной проверке аспектов используйте один аспект один раз на отзыв.

## Проверки

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тексты в тестах — искусственные технические фикстуры, изолированные во временных
БД. Они не являются корпусом студентов, не импортируются в рабочую базу и не
доказывают качество модели. Действительный отчёт macro-F1 появляется только
после обучения на предоставленном размеченном корпусе.
Отчёт выполненных проверок и ограничения: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Структура

`app.py` — запуск; `baknin/` — API, БД, агрегаты, NLP и CLI; `templates/` и `static/`
— сайт; `model_training.py` — обучение; `data/` — справочник и схема импорта;
`tests/` — проверки; `docs/` — методика и приёмка. `instance/` — локальная база,
модель и отчёты, исключены из Git. Резервируйте базу отдельно.

## Что остаётся до содержательного релиза

Собрать разрешённые отзывы, вручную разметить корпус, измерить качество и откалибровать
порог/рейтинг, подтвердить справочник вузов. Справочник содержит известные официальные
адреса; доступность сайтов в этой среде проверить не удалось. Курсовая и презентация
не входят в программный архив: их следует писать по фактическим данным и методичке.

В этой реализации не заявляется совместимость с недоступным большим исходным
`project.zip`: перенос старого кода требует отдельного доступного архива исходников.
