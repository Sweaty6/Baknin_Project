01 / ПОДГОТОВКА

Проверьте репозиторий

Откройте Sweaty6/Baknin_Project. На вкладке Code выберите ветку main. В репозитории должен находиться файл .github/workflows/pages.yml — он описывает автоматическую сборку и публикацию.

Войдите под учётной записью владельца или участника с правом изменять настройки репозитория. Для публикации не нужно устанавливать программы на компьютер: GitHub собирает файлы сайта самостоятельно.

02 / НАСТРОЙКА

Выберите GitHub Actions

  1. В репозитории откройте вкладку Settings.
  2. В левом меню найдите Code and automation → Pages.
  3. В разделе Build and deployment откройте список Source.
  4. Выберите GitHub Actions.
Settings→Pages→Source: GitHub Actions

Workflow уже находится в проекте. Дополнительный шаблон сайта выбирать не требуется. Если вкладка Pages или список Source недоступны, проверьте права своей учётной записи и доступность Pages для выбранного репозитория.

03 / ПУБЛИКАЦИЯ

Запустите готовый workflow

  1. Перейдите на вкладку Actions. Если GitHub предлагает включить workflows, разрешите их запуск для этого репозитория.
  2. В списке слева выберите Publish GitHub Pages.
  3. Нажмите Run workflow, выберите ветку main и подтвердите кнопкой Run workflow.
  4. Откройте появившийся запуск и дождитесь зелёного статуса. Сборка и публикация обычно занимают несколько минут.
Открыть Publish GitHub Pages →

Каждый последующий коммит в main также запускает публикацию автоматически.

04 / ПРОВЕРКА

Откройте опубликованный сайт

Вернитесь в Settings → Pages и нажмите Visit site. Адрес также доступен в результате завершившейся публикации на вкладке Actions.

Открыть сайт →

Для этого репозитория адрес — https://sweaty6.github.io/Baknin_Project/. Если вы публикуете копию проекта, используйте адрес из своих настроек Pages: имя владельца и репозитория будут другими.

Проверьте каталог университетов, страницу отзывов, анализ текста и методологию. Откройте карточку вуза и убедитесь, что страницы доступны по прямым ссылкам и удобно читаются на телефоне.

05 / ОБНОВЛЕНИЯ

Изменения публикуются из main

Сохраняйте изменения страниц и опубликованных данных в ветку main — напрямую или через объединение pull request. Дождитесь завершения нового запуска Publish GitHub Pages, затем обновите страницу сайта.

Если раньше сайт публиковался из gh-pages, проверьте Settings → Environments → github-pages → Deployment branches and tags: добавьте разрешённую ветку main. Это нужно для обновлений через GitHub Actions.

Каталог вузов хранится в website/data/catalog.json, отзывы для публикации — в website/data/reviews.json. При редактировании сохраняйте формат данных и добавляйте только реальные записи с проверенными источниками и разрешением на показ текста. Правила заполнения описаны в инструкции репозитория.

Каталог показывает данные, включённые в последнюю публикацию. Ввод на странице анализа не добавляет отзыв в каталог. Если подтверждённых отзывов ещё нет, сайт честно покажет пустую выборку и не будет создавать оценки.

Как работает опубликованный сайт

Страницы открываются в браузере. Текст отзыва анализируется словарными правилами на вашем устройстве и не отправляется на сервер анализа. Точность на независимом корпусе не подтверждена; результат требует проверки человеком.

06 / РЕШЕНИЕ ПРОБЛЕМ

Если публикация не удалась

Не видно Publish GitHub Pages
Проверьте наличие .github/workflows/pages.yml в main и разрешение запуска GitHub Actions в настройках репозитория.
Запуск отмечен красным
Откройте запуск на вкладке Actions и разверните первый шаг с ошибкой. Проверьте Source: GitHub Actions и сообщения в журнале. После исправления повторите запуск через Run workflow.
Сайт возвращает 404
Дождитесь успешного завершения публикации и откройте точный адрес через Visit site. Для текущего проекта в адресе должен присутствовать путь /Baknin_Project/.
Обновления ещё не видны
Убедитесь, что изменения попали в main, а последний workflow завершился успешно. Обновите страницу без кеша или проверьте сайт в новом приватном окне браузера.
Нет отзывов или рейтинга
Проверьте наличие реальных, разрешённых к публикации данных. Пустой каталог отзывов или отсутствие места при малой выборке не означают ошибку публикации.
