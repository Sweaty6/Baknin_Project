# Публичные данные сайта

Основной сайт собирается из этих JSON-файлов средствами Node.js. Python и SQLite
для изменения и публикации сайта не требуются.

- `catalog.json` — справочник вузов и параметры рейтинга.
- `reviews.json` — реальные отзывы, подготовленные для открытой публикации.
  Сейчас список пуст: искусственные отзывы для заполнения рейтинга не добавляются.
- `rules.json` — словарные правила анализа, который работает в браузере.

Чтобы добавить проверенные отзывы, откройте `reviews.json` в GitHub, внесите
изменения и сохраните их в `main`. Workflow `Publish GitHub Pages` проверит
данные, пересчитает рейтинг и обновит сайт. При ошибке публикация остановится,
а прежняя версия сайта продолжит работать; причина будет в журнале Actions.

## Справочник вузов

`catalog.json` имеет структуру
`{schema_version: 1, settings: {...}, universities: [...]}`.
В `settings` обязательны `min_reviews` — положительное целое число,
`smoothing` — конечное число от нуля, и `min_topic_reviews` — сейчас строго `3`.
Это пилотные параметры: их качество на реальном корпусе ещё не подтверждено.

Каждый вуз содержит `id`, `full_name`, `short_name`, `city`, `region`,
`official_url` и необязательное `official_url_live_verified` (по умолчанию
`false`). ID должен быть уникальным, начинаться с латинской буквы и состоять
из строчных латинских букв, цифр, `_` и `-`. Названия и местоположение —
непустые строки; официальный адрес — HTTPS URL без учётных данных.

## Отзывы

`reviews.json` — JSON-массив. Каждая запись содержит следующие поля.

| Поле | Что записать |
|---|---|
| `id` | Уникальное положительное целое число до `9007199254740991` |
| `university_id` | ID вуза из справочника; принадлежность отзыва этому вузу проверяется человеком |
| `source` | Объект с `id`, `platform`, `url`, `terms_checked_at` |
| `source.id` | Положительное целое число, общее для одного источника |
| `source.platform` | Название исходной площадки |
| `source.url` | Канонический HTTPS адрес площадки без учётных данных |
| `source.terms_checked_at` | Дата ручной проверки условий использования источника |
| `source_url` | HTTPS ссылка на исходный отзыв с тем же именем хоста, что у `source.url` |
| `source_review_id` | Стабильный ID исходной записи; можно опустить или указать `null` |
| `text` | Публичный текст, от 1 до 5000 символов; строго `null`, если показывать его нельзя |
| `published_at` | Дата исходной публикации |
| `collected_at` | Дата сбора, не раньше публикации |
| `original_score` | Исходная оценка автора: конечное число или `null`; можно опустить. На рейтинг она не влияет |
| `sentiment` | Ручная метка `positive`, `negative` или `neutral` |
| `approved` | `true`, если тональность проверена; `false`, если проверка ещё нужна |
| `verified` | Строго `true` после ручной проверки происхождения и принадлежности вузу |
| `personal_data_removed` | Строго `true` после удаления ненужных персональных данных |
| `display_allowed` | Явное `true` или `false`: разрешено ли публиковать текст и цитаты |
| `aspects` | Список тем; можно опустить, тогда используется `[]` |

Даты принимаются как `ГГГГ-ММ-ДД` или как полное время ISO 8601 с часовым
поясом, например `2026-10-14T10:30:00Z` или `2026-10-14T13:30:00+03:00`.
В опубликованном снимке даты приводятся к UTC.

Один `source.id` должен везде иметь одинаковые название, URL и дату проверки
условий. Один канонический `source.url` использует один ID; переименование
площадки не создаёт новый источник.

Каждая тема в `aspects` содержит `aspect`, `sentiment`, `approved`, `context`
и необязательное `confidence`. `sentiment` использует те же три метки,
`approved` — явное логическое значение. `context` — точная цитата из `text`
или пустая строка; при скрытом тексте он строго `null`.
`confidence` можно опустить или указать `null`: ручные метки не являются
измеренной вероятностью. Подтверждённая тема требует подтверждённого отзыва.

| `aspect` | Тема |
|---|---|
| `teaching` | Преподавание и учебный процесс |
| `career` | Практика и трудоустройство |
| `dormitory` | Общежитие |
| `infrastructure` | Инфраструктура |
| `administration` | Администрация |
| `student_life` | Студенческая жизнь |
| `finance` | Стоимость и финансы |

Один отзыв содержит не более одной записи каждой темы. В сильные и слабые
стороны входят только подтверждённые темы подтверждённых отзывов, когда есть
как минимум три подтверждения соответствующей тональности.

## Что проверяется перед публикацией

Повторный нормализованный текст для одного вуза отклоняется. Одна исходная
публикация учитывается один раз во всём корпусе: нельзя повторно добавить
отредактированный текст или назначить тот же отзыв другому вузу. Стабильный
`source_review_id` проверяется вместе с каноническим URL источника;
переименование площадки не обходит проверку. Если ID отсутствует, уникальность
проверяется по `source_url`. Общая страница с несколькими отзывами допустима
только при разных стабильных `source_review_id` у всех записей на этой странице.
Фрагмент после `#` не создаёт отдельную исходную публикацию.

Одинаковые тексты у разных вузов не отклоняются автоматически: короткие
общие фразы могут совпасть. Такие случаи нужно проверить вручную на спам
и неверную принадлежность вузу. Сборщик не скачивает страницы и не проверяет
условия площадки за человека.

Все отслеживаемые файлы здесь публичные. Если `display_allowed=false`,
замените `text` и все `context` на `null` **до коммита**. Сборка откажется
принимать скрытые тексты и цитаты. Нельзя добавлять оригинальные приватные
данные, имена пользователей, email, токены, аудит модерации или произвольные
служебные поля. Разрешённые поля перечислены выше; остальные отклоняются.
Исходные приватные материалы храните отдельно от репозитория.

Для самостоятельной проверки данных и сборки используйте команды из
основного [README](../../README.md). Только реальные разрешённые данные
должны попадать в `reviews.json`; технические фикстуры находятся в тестах.
